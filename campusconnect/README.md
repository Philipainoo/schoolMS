# CampusConnect — UEW

CampusConnect is a university community app for the University of Education, Winneba. This application lives in its own `campusconnect/` folder so the original PHP/CodeIgniter files at the repository root remain untouched.

## Included in this first conversion pass

- Next.js + TypeScript web application
- UEW-branded responsive feed and sign-in / sign-up screens
- Supabase email/password authentication
- UEW tenant lookup using the existing `institutions.slug = 'uew'` record
- Campus, academic and marketplace post channels
- Feed reading, profile names, post publishing and threaded comments against the existing RLS-protected Supabase tables
- Email confirmation messaging
- Editable student profiles with bio, programme/major, department and graduation year
- Private profile-photo uploads (JPG, PNG and WebP, 2 MB maximum) with signed image URLs
- UEW communities: create public and private groups, browse, join and leave public communities
- Member-only group discussions with author, owner and moderator post deletion
- Private-group invitations with an in-app invitation inbox and verified-member acceptance
- Owner-managed moderator promotion and removal
- Private one-to-one chats and named group conversations (up to 20 verified UEW members), with exact-username member lookup and live message updates
- Private image sharing in chats (JPG, PNG and WebP, 5 MB maximum) using signed URLs and conversation-member storage policies
- Message read receipts for one-to-one and group chats, backed by per-member read markers
- Group conversation member management: owners and administrators can add/remove members; owners can appoint administrators and transfer ownership; members can leave groups
- Live typing indicators in private and group chats using private Supabase Realtime Presence channels
- Campus events calendar/list with event details and Africa/Accra date display
- Official campus announcements with important-priority highlighting; verified faculty can publish using existing institution-scoped RLS policies
- Private notification inbox with unread indicators and live updates for post comments, direct messages and community invitations\n- Live campus feed and group discussions that refresh when new posts or comments arrive; the UI shows Realtime connection status

## Local setup

1. Install Node.js 22 or newer.
2. Open a terminal in `campusconnect/`.
3. Install dependencies: `npm install`.
4. Copy `.env.example` to `.env.local`.
5. In the Supabase dashboard for project `jfwnudfdiuopdsjqakku`, copy the public anon/publishable key into `NEXT_PUBLIC_SUPABASE_ANON_KEY`. Never use a service-role or secret key in this app.
6. Run `npm run dev` and open http://localhost:3000.

## Supabase Auth setup

In Supabase Authentication settings:
- Enable email/password sign-up.
- Keep email confirmation enabled.
- Add your local and production app URLs to the allowed redirect URLs.
- Configure a production SMTP provider before inviting the whole campus.

The UEW tenant record is already seeded. New accounts start with `verification_status = pending`; the app deliberately blocks community access until an authorised campus administrator verifies the account. Email confirmation proves control of an email inbox, not current student status. The official UEW student/faculty email domains have **not** been confirmed or configured, so do not enforce a guessed email suffix. After the university eligibility process is confirmed, provide administrators with a secure verification workflow before inviting the campus.

## Existing database

The app uses existing tables:
- `institutions`
- `users`
- `profiles`
- `posts`
- `comments`
- `groups`
- `group_members`
- `group_posts`
- `conversations`
- `conversation_members`
- `messages`
- `user_blocks`
- `group_invites`
- `campus_events`
- `announcements`
- `notifications`

The database already has row-level security enabled. Existing `campus_events` and `announcements` tables are used for the campus board: verified UEW members can read institution-scoped records, and verified faculty accounts can publish official items. The app uses only the public Supabase client and relies on those database policies; no service-role key is included. Notifications are generated by private-schema database trigger functions, are readable and markable as read only by their recipient, and are streamed through Supabase Realtime. Campus feed posts, comments and group posts are also included in the Realtime publication; subscriptions rely on the existing institution and group-membership RLS policies. The `campus-avatars` private Storage bucket is provisioned by the `campusconnect_profile_avatars` migration. Group discussion tables and tenant-safe membership policies are provisioned by `campusconnect_groups_and_discussions`; group creation is protected by the tenant-scoped `groups_insert_owner` policy; a private-schema trigger adds the creator as group admin without exposing a privileged RPC. Private group invitations, verified-recipient acceptance, moderator permissions and column-scoped role changes are provisioned by `campusconnect_group_invites_and_moderation` and `campusconnect_group_role_column_grants`. Direct-message creation is handled by the `open_direct_conversation` SECURITY INVOKER RPC. The `campusconnect_group_messaging_attachments` migration adds named group conversations, a SECURITY INVOKER group-creation RPC, and the private `campus-message-attachments` Storage bucket. The `campusconnect_reporting_blocking_rls` migration limits reports to existing same-campus posts and restricts blocks to other verified UEW members. Narrow INSERT policies enforce verified same-institution membership and block checks. Message reads and writes are limited by conversation-membership RLS, and new messages are streamed through Supabase Realtime. The `campusconnect_message_read_receipts` migration adds a per-member `last_read_at` marker; each member can update only their own marker, and the interface shows whether the latest outgoing message has been seen. The `campusconnect_group_member_management` migration adds owner/admin/member roles and narrowly scoped membership-management RPCs. Group owners can appoint administrators and transfer ownership; owners and administrators can add or remove ordinary members, and non-owner members can leave. The follow-up `campusconnect_membership_update_privilege_hardening` migration removes direct membership-row UPDATE grants and permits authenticated users to update only their own read marker; role changes remain behind the validated group-management RPCs. The `campusconnect_private_typing_presence` migration restricts private Realtime channel subscriptions and publishing to members of the matching conversation. Typing status is transient Presence data, not a stored chat message. The `campusconnect_message_edit_delete` migration lets message authors edit their own messages and soft-delete them for everyone; deleted messages remain as tombstones, and message identity/attachment fields are protected from direct updates. Attachment paths are restricted to the sending member and the conversation; reads require conversation membership. Images are limited to JPG, PNG and WebP, up to 5 MB, and are displayed through short-lived signed URLs.

## Current scope / next build steps

This is a first working web foundation, not a finished production social network. The next increments should add:
1. Message editing/deletion and typing indicators are implemented; next add richer group chat settings.
2. UEW feed reporting and member blocking controls are implemented; next add an administrator report-review queue and moderation audit trail.
3. An administrator-facing UEW member verification queue and audit trail.
4. Expo Android client sharing the same Supabase backend.


Before public launch, test the RLS policies using separate student accounts and configure the official UEW eligibility process. The legacy root PHP entry point is deliberately preserved.
